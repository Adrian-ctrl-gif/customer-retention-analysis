# Анализ лояльности пользователей Яндекс Афиши

Проект анализирует повторные покупки пользователей за июнь — октябрь 2024 года. Python-приложение загружает заказы, очищает данные, создаёт пользовательские профили и выводит аналитический отчёт в терминал.

## Структура проекта

- `main.py` — запуск анализа и вывод отчёта.
- `src/processing.py` — класс `DataProcessor`: загрузка, очистка, создание профилей и расчёт показателей.
- `requirements.txt` — зависимости проекта.
- `.env.example` — шаблон настроек подключения к базе.
- `data/` — локальные файлы заказов и курсов валют.

Файл `.env`, данные и виртуальные окружения исключены из Git.

## Установка и запуск

Проект проверен на Python 3.12.10. Команды ниже предназначены для PowerShell в Windows.

1. Клонируйте репозиторий и перейдите в его папку:

```powershell
git clone https://github.com/Adrian-ctrl-gif/mle-analiz-loyalnosti-polzovatelej.git
cd mle-analiz-loyalnosti-polzovatelej
```

2. Создайте виртуальное окружение и установите зависимости:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

3. Создайте файл настроек:

```powershell
Copy-Item .env.example .env
```

Заполните в `.env` параметры доступа к учебной базе из задания:
`DB_USER`, `DB_PWD`, `DB_HOST`, `DB_PORT`, `DB_NAME`.

4. Создайте папку для данных и скачайте курсы валют:

```powershell
New-Item -ItemType Directory -Force data
Invoke-WebRequest -Uri "https://code.s3.yandex.net/datasets/final_tickets_tenge_df.csv" -OutFile "data/final_tickets_tenge_df.csv"
```

5. Запустите анализ:

```powershell
.\.venv\Scripts\python.exe main.py
```

При первом запуске приложение загрузит заказы из базы и сохранит их в `data/afisha_orders.csv`. Для этого необходим действующий доступ к учебной базе. При следующих запусках приложение использует сохранённый файл.

## Обработка данных

В анализ включены заказы с мобильных устройств и компьютеров, кроме заказов на фильмы.

Выручка в тенге переводится в рубли по курсу на дату заказа с учётом номинала 100 тенге. Удаляются повторяющиеся записи с одинаковыми характеристиками заказа и заказы с выручкой выше 99-го перцентиля. Нулевая и отрицательная выручка сохраняются.

После очистки заново рассчитываются интервалы между заказами. Для каждого пользователя формируется профиль с количеством заказов, средними показателями и характеристиками первого сохранившегося заказа.

Повторным покупателем считается пользователь с двумя и более заказами в очищенной выборке.

## Основные результаты

Для использованной выгрузки:

- Исходное количество заказов — 290 611.
- Удалено предполагаемых неявных дубликатов — 40.
- Удалено заказов выше порога выручки 2 628,42 ₽ — 2 825.
- Осталось 287 746 заказов и 21 854 пользователя.
- Средняя выручка с заказа — 518,04 ₽.
- Доля повторных покупателей — 61,71%.
- Медианное число заказов на пользователя — 2.

После первого заказа на спорт доля повторных покупателей составляет 56,18%, после концертов — 62,16%. Наблюдаемое различие не поддерживает предположение о более высоком возврате после спорта.

В объединённой группе пяти крупнейших по числу пользователей регионов доля повторных покупателей составляет 62,74%, в остальных — 60,08%. Разница составляет 2,66 процентного пункта.

Приложение сравнивает наблюдаемые доли; статистическая значимость этих различий в нём не проверяется.

Среди изученных признаков наиболее высокую связь с группой по числу заказов показывают среднее количество билетов в заказе (φk = 0,342) и средняя выручка с заказа на пользователя (φk = 0,289).

## Рекомендации и ограничения

Можно проверить персональные предложения для покупателей концертов, театров и выставок. Эффективность предложений следует оценивать A/B-тестами с учётом затрат и дополнительной выручки.

Необходимо отдельно изучить сверхактивные аккаунты, а также происхождение нулевой и отрицательной выручки.

У пользователей, впервые купивших ближе к концу периода, было меньше времени для повторного заказа. Первый заказ в выборке не обязательно является первым заказом пользователя за всё время.

Результаты относятся к очищенной выборке. Сравнение топ-5 регионов характеризует объединённую группу, а не каждый регион отдельно.

Обнаруженные связи не доказывают причинность. Средние показатели за всю историю покупок нельзя использовать для прогноза сразу после первого заказа.

## Автоматические тесты

Проверить базовую обработку данных можно без доступа к PostgreSQL и без реальных пользовательских данных:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют только искусственно созданные заказы и проверяют конвертацию KZT в RUB, удаление выбросов, формирование профилей, интервалы между покупками и долю повторных покупателей. Они не проверяют работу подключения к учебной базе и не воспроизводят все численные показатели из раздела результатов.
